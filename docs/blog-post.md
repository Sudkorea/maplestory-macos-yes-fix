# 맥북 메이플스토리 발열: 게임 꺼도 남는 YES 프로세스 CPU 100% 임시 해결

메이플을 껐는데도 맥북이 계속 뜨거웠다. 활성 상태 보기를 확인해 보니 `YES`라는 프로세스가 CPU를 약 100%씩 쓰고 있었다. 게임을 껐다 켜다 보니 여러 개가 쌓여 있기도 했다.

고객센터에는 이미 문의했고 답변도 받았다. 일단 매번 찾아서 끄기 번거로워서, 바탕화면에서 더블클릭하면 정리되는 스크립트를 만들어 뒀다.

**[GitHub 코드와 다운로드](https://github.com/Sudkorea/maplestory-macos-yes-fix)**

게임 파일은 건드리지 않고 남아 있는 해당 프로세스만 종료한다. 근본적인 수정은 아니고 임시로 정리하는 용도다.

## 게임을 껐는데 왜 계속 뜨거울까?

내 Mac에서 확인한 핵심 증상은 이랬다.

- 메이플스토리를 종료해도 발열이 계속됐다.
- 활성 상태 보기에 `YES`가 남아 CPU를 크게 사용했다.
- 게임을 여러 번 실행하고 종료한 뒤 해당 프로세스가 여러 개 보였다.

처음에는 잠자기 방지 앱인 Amphetamine을 켜 둔 것이 영향을 줬는지 의심했다. 당시 메이플스토리를 몇 시간 켜 뒀고, Cmd+Q로 종료를 요청해도 먹히지 않는 상황도 있었다. 다만 이 두 가지가 반드시 필요한 발생 조건인지는 확인하지 못했다. 참고로 Cmd+Q는 강제 종료가 아니라 일반 종료 요청이다.

실제로 프로세스의 부모 관계를 따라가니 메이플스토리의 단축키 복구 작업과 연결돼 있었다.

## 확인해 보니 단축키 복구 작업에서 생긴 문제였다

확인한 구조를 짧게 줄이면 다음과 같다.

```text
메이플스토리 단축키 처리(set_hotkeys)
  -> 단축키 복구 스크립트(.hotkey-cache.sh)
     -> YES 프로세스
```

게임에서 사용하기 위해 바꾼 macOS 단축키를 되돌리는 과정에서 문제가 생겼다. Spotlight 관련 설정값을 읽는 데 실패했고, 그 오류 문장과 기본값 `YES`가 줄바꿈을 포함해 복구 스크립트에 들어가 있었다.

이때 줄바꿈 뒤의 `YES`가 별도 명령으로 실행됐다. 내 Mac에서는 대문자 `YES`로 실행해도 문자열을 계속 출력하는 `yes` 프로그램이 실행됐다. 이 작업이 끝나지 않으면서 CPU를 계속 쓰고 있었다.

오류가 들어간 파일과 정확한 실행 흐름은 [GitHub 원인 분석 문서](https://github.com/Sudkorea/maplestory-macos-yes-fix/blob/main/docs/analysis.md)에 정리했다. 모든 맥북 발열의 원인이 이것이라는 뜻은 아니다. 활성 상태 보기에서 같은 프로세스가 보일 때 확인할 만한 사례다.

## 고객센터에는 이미 문의했다

이 문제로 고객센터에 문의했고 답변을 받았다. 답변은 MAC 버전이 베타 서비스 중이며, 참여 기록을 바탕으로 안정성 테스트와 최적화를 진행하고, 제보 내용을 참고할 수 있도록 전달했다는 내용이었다.

![메이플스토리 고객센터 답변: MAC 베타 서비스 운영 및 제보 내용 전달 안내](https://raw.githubusercontent.com/Sudkorea/maplestory-macos-yes-fix/main/docs/support-response.png)

답변에 구체적인 원인이나 수정 일정은 없었다. 아래 스크립트를 승인했다는 내용도 없다. 그래서 현재 배포한 도구는 개인적으로 만든 임시 정리 도구로 소개한다.

## 매번 끄기 번거로워서 스크립트를 만들었다

바탕화면의 파일을 실행하면 아래 순서로 처리한다.

1. 내 계정의 메이플 단축키 복구 작업에 연결된 `YES`가 있는지 확인한다.
2. 조건이 일치하면 해당 복구 작업과 `YES`를 종료한다.
3. 다시 확인하고 결과를 표시한다. 대상이 없으면 그대로 끝난다.

`YES`라는 이름만 보고 모두 종료하지는 않는다. 연결된 부모 프로세스, 실행 경로, 사용자 소유 여부까지 확인하도록 했다.

### 사용 순서

1. 메이플스토리를 종료한다.
2. [GitHub 최신 릴리스](https://github.com/Sudkorea/maplestory-macos-yes-fix/releases/latest)에서 `maplestory-hotkey-cleanup.zip`을 받는다.
3. 압축을 풀어 `kill-maplestory-hotkey-loop.command`를 바탕화면에 둔다.
4. 더블클릭한다.

처음 실행할 때 권한이나 macOS 보안 확인이 나타날 수 있다. 해당 상황별 실행 방법과 검사만 하는 옵션은 [저장소 사용 설명](https://github.com/Sudkorea/maplestory-macos-yes-fix#사용-방법)에 정리해 뒀다.

이 스크립트는 게임 설치 파일이나 사용자 설정 파일을 수정하지 않는다. 별도 설치 프로그램이나 상주 앱도 없다. 단, 이미 중단된 키보드 설정 복구를 대신 완료해 주는 기능은 없으므로 단축키가 달라져 있다면 시스템 설정에서 확인해야 한다.

## 완전히 해결되는 건가?

이미 남아 있는 문제 프로세스를 정리하는 데 목적이 있다. 원인 파일을 고치는 패치가 아니므로, 다음에 게임을 실행한 뒤 같은 현상이 생길 수 있다.

최초 증상은 macOS 15.7.7 / Apple Silicon에서 확인했다. 2026년 9월 15일에는 macOS 26.6.1에서 다시 점검했다. 예전 오류 파일은 남아 있었지만, 같은 읽기 명령으로 오류 문장과 `YES`가 함께 생성되는 현상은 이번에는 재현되지 않았다.

이때 실제 장애 프로세스도 없어서 공개 버전의 종료 처리는 모의 프로세스로 검증했다. 최신 게임에서 문제가 다시 발생하는지까지 새로 재현한 것은 아니다. 이 글은 내가 겪은 사례와, 같은 프로세스가 남아 있을 때 쓸 수 있는 대응 방법을 기록한 것이다.

비슷한 경험은 [인벤의 다른 사용자 제보](https://www.inven.co.kr/board/maple/5974/6776497)에서도 찾을 수 있었다. 다만 증상이 같다고 모든 환경의 원인이 같다고 단정할 수는 없다.

게임을 껐는데도 계속 뜨겁다면, 우선 활성 상태 보기의 CPU 탭에서 `YES`가 남아 있는지 확인해 보자. 같은 증상으로 매번 프로세스를 정리하고 있다면 아래에 코드와 실행 파일을 공개해 뒀다.
