# YES CPU 점유 문제: 확인 근거와 범위

작성일: 2026-09-15. 개인 Mac에서 확인한 사례이며 넥슨의 공식 기술 분석이 아닙니다. 아래 경로의 사용자 이름은 `$HOME`으로 바꿨습니다. 오류 예시는 설명용 텍스트이며 실행 명령이 아닙니다.

## 확인한 실행 흐름

설치된 `set_hotkeys`를 읽어 보면 기존 `.hotkey-cache.sh`가 있을 때 먼저 실행합니다. 이후 게임에 맞춰 macOS 단축키를 바꾸고, 기존 값을 되돌리는 명령들을 캐시 스크립트에 기록합니다. 게임 프로세스가 끝나면 이 복구 스크립트를 실행하는 경로도 있습니다.

```text
set_hotkeys
  -> .hotkey-cache.sh
     -> YES .../com.apple.symbolichotkeys.plist
```

문제가 생긴 캐시 파일에는 아래 두 줄이 들어 있었습니다.

```text
plutil -replace AppleSymbolicHotKeys.64.enabled -bool $HOME/Library/Preferences/com.apple.symbolichotkeys.plist: Could not extract value, error: No value at that key path or invalid key path: AppleSymbolicHotKeys.64.enabled
YES "$HOME/Library/Preferences/com.apple.symbolichotkeys.plist"
```

## 왜 YES가 명령이 되나요?

1. `AppleSymbolicHotKeys.64.enabled` 값을 추출하는 `plutil` 호출이 실패했습니다.
2. 남아 있는 캐시에는 오류 문장까지 기록돼 있습니다. 읽어 본 생성식에서 오류 문장이 표준 출력으로 나오면, 표준 오류만 숨기는 처리로는 이 문장이 제거되지 않습니다.
3. 실패 시 기본값 `YES`를 출력하는 처리까지 실행되면서, 변수에 `오류 문장 + 줄바꿈 + YES`가 들어갔습니다.
4. 이 값을 검증하지 않고 복구용 셸 명령에 넣으면서 줄바꿈 뒤의 `YES`가 독립적인 명령이 됐습니다.
5. 확인한 파일 시스템에서는 대문자 `/usr/bin/YES`와 소문자 `/usr/bin/yes`의 inode가 같았습니다. 따라서 해당 줄은 문자열을 계속 출력하는 `yes` 프로그램을 실행했습니다.

캐시의 `YES` 줄에서 실행이 멈춰 있으므로 뒤에 있는 다른 설정 복구와 캐시 삭제까지 도달하지 못합니다. 기존 캐시를 다음 실행에서 다시 읽는 경로는 재실행 때 같은 현상이 반복될 수 있는 이유를 설명합니다. 실제 초기 조사에서도 여러 `YES` 프로세스가 누적된 것을 관찰했습니다.

이 설명은 읽어 본 코드, 생성된 파일, 당시 프로세스의 부모 관계에 근거한 분석입니다. 다만 오류 파일을 처음 만들던 순간의 출력 스트림은 보존하지 않았고, 단축키 항목이 처음부터 없었던 이유와 모든 환경에서의 발생 조건은 확정하지 못했습니다.

**현재 환경에서는 생성 과정을 새로 재현하지 못했습니다.** macOS 26.6.1에서 같은 읽기 명령에 표준 오류 리디렉션을 적용하면 오류 문장은 사라지고 기본값 `YES`만 캡처됐습니다. 예전 캐시가 남아 있는 것과 현재 OS에서도 같은 캐시가 새로 생성되는 것은 구분해야 합니다. OS 변경 때문에 달라진 것인지는 별도 비교 검증하지 않았습니다.

## 관찰과 의심 조건

| 항목 | 확인 수준 |
| --- | --- |
| 게임을 꺼도 `YES`가 남고 개별 CPU 사용량이 약 100%까지 올라감 | 초기 로컬 조사에서 관찰 |
| `set_hotkeys -> .hotkey-cache.sh -> YES` 부모 관계 | 초기 로컬 조사에서 확인 |
| 캐시에 오류 문장 다음 줄로 `YES`가 기록됨 | 초기 조사 및 2026-09-15 파일 재확인 |
| Amphetamine 실행 후 메이플스토리를 수 시간 켜 둠 | 당시 사용 조건, 인과관계 미확정 |
| Cmd+Q로 종료를 시도했으나 종료되지 않음 | 당시 관찰, 인과관계 미확정 |

Cmd+Q는 일반 종료 요청입니다. 강제 종료 단축키로 표현하지 않았습니다. Amphetamine이나 장시간 플레이가 반드시 필요한 재현 조건이라고 확인한 것은 아닙니다.

## 이번 공개 준비에서 확인한 것

2026-09-15 환경은 macOS 26.6.1 (25G76), arm64입니다. 이전 장애 관찰 당시 macOS 15.7.7과 구분합니다.

- 설치된 `set_hotkeys`와 남아 있는 캐시 파일을 읽었습니다.
- 사용자 설정에 대한 읽기 전용 `plutil -extract` 호출에서 동일한 키 경로 오류를 확인했습니다.
- 같은 호출에서 표준 오류를 숨기면 기본값 `YES`만 캡처됐습니다. 오류 문장과 기본값이 함께 기록되는 생성 과정은 현재 환경에서 재현되지 않았습니다.
- `/usr/bin/YES`와 `/usr/bin/yes`가 같은 inode를 가리키는 것을 확인했습니다.
- 이 시점에는 해당 장애 프로세스가 실행 중이지 않았습니다.
- 공개용 도구의 실제 종료 동작은 모의 프로세스 검사로 확인했습니다. 최신 게임 클라이언트를 새로 실행해 장애를 재현하지 않았습니다.

재확인한 설치 파일의 SHA-256:

```text
set_hotkeys
73ec9a0d7f7b7b9f64e42ec86eacf09cefcc55da1d8b94e02017688ef18af4a2
```

이 해시는 관찰한 파일을 구분하기 위한 값이며, 공식 배포본의 진위나 최신 버전을 보증하지 않습니다. 게임 스크립트 전체는 저장소에 포함하지 않습니다.

## 대응 범위

이 도구는 이미 남아 있는 해당 프로세스와 복구용 셸을 종료합니다. 원인 파일 수정, 게임 패치, 키보드 설정 복구는 수행하지 않습니다. 따라서 이후 실행에서 재발할 수 있고, 중단된 복구 때문에 남은 키보드 설정은 별도로 확인해야 합니다.

근본 대응은 클라이언트 측에서 추출 실패를 명확히 처리하고, 기본값을 검증한 뒤, 오류 출력이나 줄바꿈이 실행할 셸 코드에 들어가지 않도록 하는 것입니다. 이는 분석에 따른 제안이며 공식 수정안이 아닙니다.

## 고객센터와 외부 자료

직접 문의 후 받은 [고객센터 답변 이미지](support-response.png)에는 MAC 버전 베타 운영, 안정성 테스트/최적화, 제보 내용 전달이 안내돼 있습니다. 답변의 수신 날짜는 첨부 이미지에 표시돼 있지 않아 임의로 적지 않았습니다. 구체적인 결함 인정이나 수정 완료로 해석하지 않습니다.

[2026-06-25 인벤 제보](https://www.inven.co.kr/board/maple/5974/6776497)에도 게임 재실행 후 여러 `YES` 프로세스가 남고 발열이 생겼다는 경험이 올라와 있습니다. 증상이 유사하다는 자료이며, 작성자의 환경에서도 같은 코드 경로가 원인이었는지는 확인하지 않았습니다.

[Nexon 글로벌 지원의 macOS Keyboard Shortcut Settings](https://support-maplestory.nexon.com/hc/en-us/articles/48271602089108-macOS-Keyboard-Shortcut-Settings)는 macOS 단축키 충돌 설정을 다루는 참고 문서입니다. 한국 서비스의 이 결함에 대한 공식 해결 공지로 인용하지 않습니다.
